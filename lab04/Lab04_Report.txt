1. The Deadlock Problem (Phase 2):
จากการรัน deadlock_simulation.py พบว่าระบบเกิดอาการค้างสนิท (Deadlock) ไม่สามารถทำงานจนจบได้ สาเหตุเกิดจากเงื่อนไขการรอเป็นวงกลม (Circular Wait) โดย Model A ถือครอง GPU 0 แล้วรอ GPU 1 ในขณะเดียวกัน Model B ก็ถือครอง GPU 1 แล้วรอ GPU 0 ทำให้ทั้งสองโปรเซสติดล็อคและรอกันเองอย่างไม่มีที่สิ้นสุด

2. Deadlock Avoidance by Lock Ordering (Phase 3.1):
เราสามารถแก้ปัญหาการค้างได้ในไฟล์ deadlock_avoidance.py โดยใช้กฎการเรียงลำดับทรัพยากร (Strict Ordering Rule) ซึ่งบังคับให้ทุกโมเดลต้องขอถือครอง GPU 0 ให้สำเร็จก่อน จึงจะมีสิทธิ์ขอ GPU 1 ได้ วิธีนี้เป็นการทำลายเงื่อนไข Circular Wait ทำให้โมเดลสามารถสลับกันทำงานจนเสร็จสมบูรณ์ได้โดยไม่ค้าง

3. Banker's Algorithm (Phase 3.3):
ในระบบที่มีทรัพยากรซับซ้อน OS Scheduler จะใช้อัลกอริทึมของ Banker เพื่อประเมินสถานะความปลอดภัย (Safe State) ก่อนที่จะอนุมัติทรัพยากรให้โปรเซสใดๆ จากการรัน bankers_algo.py อัลกอริทึมได้คำนวณลำดับการทำงานที่ปลอดภัยออกมาเป็น Job_1 -> Job_2 -> Job_0 ซึ่งหมายความว่า หาก OS ปล่อยทรัพยากรให้ตามลำดับนี้ ระบบจะสามารถทำงานทุก Job จนเสร็จสิ้นได้โดยไม่เกิด Deadlock
