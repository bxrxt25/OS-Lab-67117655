2. System Observation (htop):
จากการใช้ htop สังเกตการทำงาน พบว่าเมื่อรันสคริปต์แบบ Multithreading (ใช้ Thread) การทำงานของ CPU จะไม่สามารถดึงศักยภาพออกมาได้เต็มที่ (อาจมีแค่ 1 คอร์ที่ทำงาน 100% หรือสลับคอร์ไปมา แต่ยอดรวมไม่เกิน 1 คอร์) ในขณะที่เมื่อรันแบบ Multiprocessing (สร้างโพรเซสใหม่) จะพบว่า CPU ทั้ง 2 คอร์ถูกใช้งานเต็มที่ถึง 100% พร้อมกันทั้งคู่

3. Analysis (The GIL):
สาเหตุที่การทำ Multithreading ไม่ทำให้โค้ดทำงานเร็วขึ้นเลย เป็นเพราะภาษา Python มีกลไกที่เรียกว่า Global Interpreter Lock (GIL) ซึ่งจะล็อกและอนุญาตให้มีเพียง 1 Thread เท่านั้นที่สามารถประมวลผลโค้ดไบต์ของ Python ได้ในแต่ละช่วงเวลา[cite: 1] ทำให้ OS ไม่สามารถกระจายเธรดข้าม CPU หลายคอร์เพื่อช่วยกันประมวลผลงานหนักๆ (CPU-bound) ได้อย่างมีประสิทธิภาพ
ดังนั้น Multiprocessing จึงเป็นทางเลือกที่ดีกว่าสำหรับงานหนักๆ อย่าง Machine Learning data augmentation เพราะการแยกโพรเซสจะทำให้แต่ละโพรเซสมีพื้นที่หน่วยความจำและมี GIL เป็นของตัวเองแยกจากกันอย่างเด็ดขาด (True Parallelism) ทำให้ OS สามารถสั่งให้ CPU ทุกคอร์ทำงานไปพร้อมๆ กันได้ ส่งผลให้เวลาโดยรวมลดลงอย่างเห็นได้ชัด
*หมายเหตุเพิ่มเติม: ในการสร้างโพรเซส (fork) โพรเซสแม่จำเป็นต้องเรียกใช้คำสั่ง os.wait() เสมอ เพื่อป้องกันไม่ให้โพรเซสลูกกลายเป็น Zombie Process
