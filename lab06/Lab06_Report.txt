1. FIFO vs LRU (Phase 2):
อัลกอริทึม LRU ทำงานได้ดีกว่าและเกิด Page Fault น้อยกว่า เพราะมีกลไกที่อิงจากการใช้งานจริง โดยมันจะเลือกลบหน้าเพจที่ "ไม่ได้ถูกเรียกใช้งานมานานที่สุด" ออกไปก่อน (อิงหลัก Temporal Locality) ทำให้เพจที่เพิ่งถูกใช้งานและมีโอกาสจะใช้ซ้ำยังคงอยู่ใน RAM ในขณะที่ FIFO จะเลือกลบเพจที่โหลดเข้ามาใน RAM ก่อนสุดออกไปเสมอ โดยไม่สนใจเลยว่าเพจนั้นกำลังจะถูกเรียกใช้อีกในเร็วๆ นี้หรือไม่ จึงเกิด Page Fault บ่อยกว่า

2. Understanding Thrashing (Phase 3):
Thrashing คือภาวะที่ RAM ของระบบเต็มจน OS ต้องสลับข้อมูลไปมาระหว่าง RAM กับฮาร์ดดิสก์ (Swapping) ตลอดเวลาอย่างหนักหน่วงครับ สาเหตุที่ Scenario 2 ใช้เวลาประมวลผลนานกว่ามาก เป็นเพราะความเร็วในการอ่าน/เขียนข้อมูลบนฮาร์ดดิสก์ (Disk I/O) นั้นช้ากว่า Physical RAM มหาศาล CPU จึงต้องเสียเวลาไปกับการรอคอยข้อมูลแทนที่จะได้ใช้เวลาไปกับการประมวลผลงานจริงๆ

3. AI Engineering Decision:
การลด `batch_size` จะช่วยลดปริมาณข้อมูลที่โมเดล AI ต้องโหลดเข้าไปประมวลผลในแต่ละรอบครับ พอชุดข้อมูลมีขนาดเล็กลงจนสามารถจัดเก็บลงใน Physical RAM ได้พอดีทั้งหมด OS ก็ไม่จำเป็นต้องใช้วิธี Swapping สลับข้อมูลลงฮาร์ดดิสก์อีกต่อไป เมื่อไม่มีการทำ Disk I/O ปัญหา Thrashing จึงหายไปและระบบกลับมาทำงานได้เร็วตามปกติครับ
